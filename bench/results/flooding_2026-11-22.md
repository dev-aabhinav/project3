uniform key inside a range). Warm-up 300k lookups; A = 50k lookups; B = full scan with 1 lookup per
200 scanned keys (~5k lookups); C = 50k lookups right after the scan (first 5k = recovery window).
OS page cache dropped before each phase. disk % = lookups needing >= 1 pool miss (deterministic);
latencies in microseconds, median of 3 reps per process run.

First design (scrambled key-level Zipf, 10 lookups per scanned page, page-hit-rate metric) showed no
flooding: the upper tree levels kept page hit rate >= 75%, the hot keys covered almost every leaf, and
frequent lookups kept refreshing hot pages. Redesigned as above.
